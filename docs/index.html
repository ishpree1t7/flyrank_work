Abstract

This project asks which content pages should be prioritized for editorial review based on observable search and engagement signals. Using a 30,000-row anonymized starter dataset of real production search performance, a Random Forest model was trained to rank pages by likelihood of decline. On a client-holdout validation split the model achieved Precision@50 of 0.74, compared with 0.24 for a transparent rule-based baseline — roughly a 3× improvement. The output is a ranked review queue with reason codes intended as decision support for content teams, not an automated publishing system. All claims remain observational and directional; the work does not claim to predict ranking-algorithm changes or guarantee traffic recovery.

1. Introduction / Problem

Content teams face a constant prioritization problem: given thousands of live pages, which ones should be reviewed first for possible refresh, expansion, or rewrite? Looking only at raw traffic or a single metric often misses pages that still have demand but are losing visibility or engagement.

This work supports a concrete decision: which pages enter the next editorial review queue. A content manager receives a ranked list, inspects the top items, and decides the appropriate action (refresh, monitor, expand, or leave alone). The cost of a false positive is wasted editorial time; the cost of a false negative is missed opportunity on a declining page that still attracts impressions.

Machine learning is useful here because many weak but complementary signals (impressions, position, CTR, engagement, freshness, content length) can be combined into a single prioritization score that is still transparent enough for human review.

2. Data

The analysis uses the anonymized starter dataset that ships with the FlyRank ML Internship repository:

  • Source: data/raw/content_refresh_anonymized.csv
  • Size: 30,000 rows × 44 columns (one row per pseudonymized content item)
  • Clients: 32 pseudonymized clients
  • Window: trailing 90-day metrics
  • Declining-label rate: 54.2 %

Columns that could identify clients, domains, URLs, titles, or raw queries were never used as features and do not appear in any public output. Rate columns (CTR, engagement rate, etc.) are stored as percentages ×100 (e.g. 0.76 means 0.76 %). The label-derived fields trend_direction and trend_pct were used only to define the target and were excluded from the feature set to prevent leakage.

3. Methodology

Label definition

is_declining_label = 1 when trend_direction == "down", otherwise 0. This is an evaluation-only target derived from observed performance trend; it is never used as a model feature.

Features

The model used only observable signals available before any future outcome: log-transformed impressions and clicks, average position, content age, character and word counts, CTR, scroll rate, days with impressions/sessions, and related engineered columns. Top contributing features (by importance) included days with impressions, log impressions (90d), average position, and content age.

Baseline

A transparent hand-written rule score was built first. It combines simple thresholds on trend, demand, CTR, and engagement to produce a ranked list and reason codes. This baseline is intentionally readable so any lift from the learned model can be trusted.

Validation design

Client-holdout split: entire clients are held out of training so the model is evaluated on unseen clients. All metrics reported below use the same holdout.

Leakage checks

trend_direction and trend_pct were confirmed absent from the feature matrix. Pseudonymous client and content IDs were used only for grouping, never as predictive features. No future information relative to the 90-day window entered the feature set.

4. Results

On the client-holdout split the Random Forest model substantially outperformed the rule baseline on the primary ranking metric (Precision@50). Base rate of the positive class is 54.2 %, so a naïve always-positive classifier would already score around that level; the model’s lift is therefore meaningful.

5. Limitations & Honest Framing

  • The model ranks pages that historically showed decline; it does not prove that refreshing those pages will recover traffic.
  • Results are based on a 30 k-row anonymized starter slice, not the full multi-million-row warehouse. Absolute numbers may shift with more data.
  • Client-holdout evaluation reduces leakage risk but does not simulate every possible future traffic regime or algorithm update.
  • Reason codes and feature importances are descriptive, not causal explanations of ranking changes.
  • The output is decision support only. Human editorial judgment remains required before any content change is published.

All language in this paper is intentionally limited to observed patterns, measured lift, and directional decision support.

6. Ranked Recommendations (Action Playbook)

The practical output is a ranked review queue. A content manager can use it tomorrow as follows:

  1. Start with the high-confidence slice (top ~3,600 items). These carry the strongest combined signal of decline + remaining demand.
  2. Read the reason codes attached to each page (e.g. low CTR on a still-visible page, declining trend with solid impressions). They give an immediate editorial hypothesis.
  3. Manually verify the live page, recent changes, and business context before acting. The model has no access to brand guidelines or upcoming campaigns.
  4. Treat medium-confidence items as a secondary queue once the high-confidence set is cleared.
  5. Monitor, do not auto-publish. The safest production use is to feed the ranked list into an existing editorial workflow, not to trigger automatic rewrites.

This ordering already beats the transparent rule baseline by a clear margin on the holdout set, while remaining fully inspectable.
